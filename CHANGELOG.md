# Changelog

Все заметные изменения проекта документируются в этом файле.

## [7.5] — 2026-11-10

### Изменено
- **Уточнена схема версий.** В записи `7.0` было сказано, что `X` — релиз с новыми возможностями, а `Y` — патч, но на практике каждый выпуск увеличивал `Y`, включая релизы с новыми возможностями (`7.1` — перевод длинных текстов и `/logs`, `7.2` — разделы `/help`). Формулировка приведена к фактической схеме: **`Y` — порядковый номер любого релиза в серии** (новые возможности, исправления, оптимизации или только документация — номер всё равно следующий), **`X` — номер серии** и двигается только по крупному поводу сбросом `Y` в `0`. Нумерация уже выпущенных версий не менялась, теги `v7.1`–`v7.4` остаются на месте.

## [7.4] — 2026-11-10

### Исправлено
- **Pre-release версии больше не выдаются за обновление.** `v7.3-rc1` разбирался как `(7, 3, 1)` и считался новее `7.3` — `/update` предлагал «обновиться» на уже установленную версию. Теперь суффикс `-rc1` / `-beta.2` / `+build` только понижает ранг: `v7.3-rc1` < `v7.3`, а `v7.4-rc1` по-прежнему новее `7.3`.
- **Варианты стилей в цепочке провайдеров.** Возможности цепочки брались только у первого провайдера (`supports_styles = providers[0].supports_styles`), поэтому `google → openai` вообще не показывал карточки стилей, а при уходе основного провайдера в cooldown запрос на три тональности молча возвращал **одну** карточку вместо трёх. Теперь флаг считается по всей цепочке, а запрос стилей уходит провайдеру, который их умеет.
- **`TextTooLongError` не рвал цепочку без нужды.** Локальная ошибка «текст длиннее лимита» ре-рейзилась сразу, поэтому запасной провайдер с бóльшим `MAX_TEXT_LENGTH` не получал шанса. Теперь переход происходит, только если следующий провайдер действительно принимает текст длиннее.
- **Дубли UTF-16-хелперов.** `utf16_len` и `build_utf16_offsets` были реализованы и в `utils/utf16.py`, и в `utils/formatting.py` — реализации могли разойтись; во втором модуле остался реэкспорт.
- **Мелочи:** подсказка `/ignore` теперь объясняет, что память `@username` очищается при перезапуске; обработчики `SIGINT`/`SIGTERM` в webhook-режиме ставятся **до** бинда порта (иначе сигнал во время старта не обрабатывался); в русской панели группы кнопка называлась «🗑 Кнопка 🗑» — эмодзи задваивался.

### Добавлено
- **Задержка перевода в `/status`.** Под блоком цепочки провайдеров — строка `⏱ Задержка: 280 мс p50 / 1.1 с p95 / 2.4 с p99 (замеров: 512)`. Хранится только кольцевой буфер из 512 чисел без всяких текстов и ID; перцентили считаются по требованию (экран владельца открывается редко).
- **`TelegramRetryAfter` обрабатывается.** `TelegramRetryAfter` наследуется от `TelegramAPIError`, поэтому флуд-лимит Telegram («Retry After») раньше проглатывался широкими `except TelegramAPIError` как обычная ошибка. Для автоматических путей (репост перевода в группе, удаление черновика `>`, отправка в личке) добавлен `utils/telegram.py::call_with_retry`: повтор, если Telegram просит подождать не больше 3 с, и честный отказ, если дольше.
- **Повтор `get_me()` при старте.** Если Telegram недоступен в момент запуска, бот делает 4 попытки с задержкой 2 → 4 → 8 с вместо немедленного падения.
- **Property-тесты в репозитории** (`tests/test_property_invariants.py`, фиксированный seed, без новых зависимостей): `restore(prepare(x)) == x`, `join(split(x)) == x` на реальной длине, полный round-trip UTF-16-смещений и отказ для смещений, попадающих на младшую половину суррогатной пары.

### Изменено (оптимизации)
| Путь | Было (v7.3) | Стало (v7.4) |
|---|---|---|
| `prepare_text_for_translation`, 2100 симв. | 209 мкс | **120 мкс** (−43 %) |
| `restore_formatted_text`, 2100 симв. | 213 мкс | **128 мкс** (−40 %) |
| `_rebase_entities_from_map`, 4 сущности | 220 мкс | **27 мкс** (−88 %) |
| Перевод длинного текста | ~9 последовательных round-trip'ов | **1 параллельный** |

- **`U16OffsetMap` больше не строит массив смещений.** Раньше для текста с эмодзи строился O(n)-массив префиксных сумм питоновским циклом с `ord()` на каждый символ — это было 74 % времени `restore_formatted_text`. Теперь хранятся только позиции астральных символов (их k): `u16(p) = p + bisect_left(a, p)`, обратно — по списку «дыр». O(log k) вместо O(n) по памяти и времени.
- **Чанки длинного текста переводятся параллельно** (`asyncio.gather` под существующим `concurrency_sem`). Сообщение на 4096 символов при `MAX_TEXT_LENGTH=500` — это ~9 частей, которые раньше шли строго друг за другом (~2.7 с вместо ~300 мс). Порядок сохраняется, при ошибке одной части остальные отменяются, а токен rate-limit по-прежнему тратится один на всё сообщение.
- **`_crosses_verbatim_boundary`** — бинарный поиск по отсортированным verbatim-спанам вместо линейного перебора.

### Проверки
- `ruff check .` чисто, `shellcheck install.sh` OK, CI (Python 3.11–3.14) зелёный.
- **255 passed** (было 228): +27 тестов — property-инварианты, pre-release версии, `supports_styles`/`TextTooLong` в цепочке, перцентили задержки, `call_with_retry`, повтор `get_me()`, параллельность чанков и отмена «братьев» при ошибке.
- Дифференциальный фуззинг нового кода против v7.3: prepare/restore на 8000 случайных текстах с сущностями, глоссарием и эмодзи — **0 расхождений**.

## [7.3] — 2026-11-10

### Исправлено
- **`truncate_preview` больше не «заворачивает» строку при крошечном лимите.** При `limit <= 1` срез `text[:limit - 1]` уходил в отрицательную область и возвращал почти весь исходный текст вместо короткого превью; теперь возвращается один символ «…» (или пустая строка для пустого ввода). В продакшене использовался только `limit=80`, так что на заголовки inline-карточек это не влияло.
- **Прогон кэша больше не портит статистику попаданий.** Проверка «перевод уже тёплый» перед debounce-задержкой проходила через обычный `get()` и считалась промахом на каждом нажатии клавиши; для неё добавлен отдельный `peek()`, не трогающий счётчики `hits`/`misses`. Цифры в `/status` снова отражают реальные обращения к провайдеру.

### Изменено (оптимизации горячего пути)
- **Подготовка текста к переводу заметно быстрее.** Пошаговое кодирование заменено копированием целых отрезков между маркерами, интервалы verbatim-блоков (ссылки, код, упоминания, глоссарий) хранятся отсортированными и проверяются бинарным поиском вместо линейного перебора, а регулярки глоссария и маркеров компилируются один раз и кешируются. Замеры на тексте 2100 символов: подготовка **1058 → 437 мкс** (−59 %), восстановление **361 → 209 мкс** (−42 %); на коротких сообщениях (70 символов) **51 → 33 мкс** и **31 → 24 мкс**.
- **Пересчёт смещений сущностей Telegram больше не квадратичный.** `_rebase_entities_from_map` перебирал карту смещений линейно для каждого `MessageEntity`; теперь это бинарный поиск: **563 → 16 мкс** на сообщении с четырьмя сущностями (−97 %).
- **Общий слой UTF-16-смещений.** Вычисление смещений вынесено в `mivta/utils/utf16.py` (`utf16_len`, `has_astral_chars`, `build_utf16_offsets`, `U16OffsetMap`): для текста без эмодзи это O(1) по памяти и времени и без построения списка вообще.
- **Общий ключ кэша.** Дайджест запроса для кэша и для singleflight живёт в одном месте — `mivta/utils/digest.py`; дублирующая реализация из `pipeline.py` удалена.
- **Кэш чистится только когда надо.** Полный обход записей на предмет истёкшего TTL запускается лишь при заполнении кэша, а не на каждую запись.

### Техническое
- Удалены устаревшие `# noqa` (на неиспользуемых правилах) в `service.py` и `logtail.py`, `os.replace` → `Path.replace`, убраны лишние приведения к `int()` в `/status`, `__all__` в `mivta/utils` отсортирован, мёртвый `_overlaps_any` удалён.
- Новые тесты: `tests/test_utf16_and_digest.py` (карта UTF-16-смещений и дайджест), регрессионные тесты на `truncate_preview` с крошечным лимитом и на статистически-нейтральный `peek()` с вытеснением истёкших записей. Всего 224 теста (было 204).

## [7.1] — 2026-11-10

### Добавлено
- **Перевод длинных текстов**: сообщения длиннее `MAX_TEXT_LENGTH` (по умолчанию 500 символов) больше не отбрасываются ни в автоматизации чатов, ни в группах. Текст режется на части по границам предложений и слов (максимум 12 частей), каждая часть переводится отдельно, а результат склеивается обратно — лимит теперь один: длина сообщения Telegram (4096 символов, для подписей — 1024). Ссылки, код, `@упоминания`, глоссарий и оформление (`<s0>…</s0>`) маскируются до разбиения, поэтому на стыках частей ничего не рвётся. Одно сообщение по-прежнему тратит один запрос к лимиту (rate-limit), даже если частей несколько.
- **Команда `/logs` (только `OWNER_ID`)**: последние записи уровня WARNING и выше прямо из памяти процесса — «📋 Логи ▸» есть и в панели `/status`. Кнопки «🔄 Обновить» и «🧹 Очистить» обновляют то же сообщение. В буфере лежат только наши собственные служебные записи (ошибки провайдеров, перезапуски, предупреждения конфигурации): тексты сообщений, inline-запросы и переводы в логи не попадают по-прежнему, длинные строки обрезаются до 300 символов, а сам буфер — кольцевой (200 записей).

### Изменено
- **В `/status` при ненастроенном `OWNER_ID` показывается только числовой Telegram ID**: строка «Добавьте `OWNER_ID=<id>` и перезапустите сервис» вместо путей к конфигу — панель владельца не раскрывает раскладку сервера.

## [7.0] — 2026-11-10

> **Новая схема версий — двухкомпонентная `X.Y`** (уточнено в [7.5]):
> - **`Y` — порядковый номер релиза внутри серии.** Увеличивается на единицу для каждого выпуска, независимо от его состава: новые возможности, исправления, оптимизации или только документация — номер всё равно следующий (`7.3 → 7.4 → 7.5`).
> - **`X` — номер серии.** Двигается только по крупному поводу, когда серия исчерпана или меняется что-то принципиальное; при этом `Y` сбрасывается в `0`.
> - Тег всегда полный, без третьего компонента: `v7.5`, но не `v7.5.0` и не `v7.5.1`.
>
> Прежние записи `0.x` сохранены для истории, старые теги не переименовывались.

### Добавлено
- **Компактный экран настроек (`/settings`)**: вместо пятистрочного списка — одна строка состояния (`🌍 RU ⇄ EN · Нейтральный`), строка доп. языков карточек и подсказка по быстрым фильтрам; полная инструкция вынесена в отдельную команду и за кнопку «ℹ️ Как пользоваться», так что панель помещается в один экран.
- **Отдельная команда `/help`**: полная справка (инлайн-режим, автоматизация чатов, группы, список команд) с кнопкой «◂ Настройки», которая превращает это же сообщение в панель настроек; `/settings` и `/help` больше не дублируют друг друга.
- **Единая панель владельца**: в `/status` добавлен раздел «🛠 Обслуживание» (состояние обновления/перезапуска из Telegram) и кнопки «🛠 Обслуживание ▸» и «🔄 Перезапустить», а из экрана обновления можно вернуться обратно кнопкой «📊 Статус» — три команды `/status`, `/update`, `/restart` работают и по отдельности, но живут в одном интерфейсе.

### Изменено
- **Единая терминология в русском интерфейсе**: «Inline Mode» → «инлайн-режим», «Secretary Mode» → «автоматизация чатов» (английское название в `@BotFather` указано в скобках), «Доп. языки Inline» → «Доп. языки карточек».

## [0.7.0] — 2026-11-10

### Добавлено
- **Обновление и перезапуск бота прямо из Telegram (`/update` и `/restart`, только для `OWNER_ID`)**: владелец бота в личном чате видит, какая ревизия/версия доступна (проверка идёт по `git fetch` ветки `MIVTA_BRANCH`, а для установок с правами root — по последнему релизу GitHub `MIVTA_UPDATE_REPO`), и нажатием одной кнопки применяет обновление: бот ставит маркер в `data/`, привилегированный юнит `mivta-update.path` выполняет `install.sh --self-update` (git pull, переустановка зависимостей, `systemctl restart`), после чего новый процесс сам пишет владельцу в то же сообщение «обновлено v0.6.0 → v0.7.0»; если обновление не применилось — приходит предупреждение с той же информацией. Перезапуск (`/restart`) для привилегий не нужен вовсе: процесс корректно останавливает приём апдейтов и подменяет сам себя (`os.execv`), сохраняя PID и systemd-юнит.
- **Безопасные стратегии обновления и аварийные выключатели**: `MIVTA_UPDATE_CMD` / `MIVTA_RESTART_CMD` для Docker и других схем (argv без shell, операторы `&&`, `|`, `;` отклоняются на этапе чтения конфигурации), автоматический выбор стратегии (`self` — если бот владелец своего каталога, `trigger` — классическая установка `install.sh`, `command`, `manual`), отказ от самостоятельного обновления при изменении `requirements.txt` / `pyproject.toml`, а также `SELF_UPDATE=false` / `SELF_RESTART=false` и `--no-remote-update` для полного отключения функции.

## [0.4.0] — 2026-11-10

### Добавлено
- **Умная автозамена недоступных API с карантином (`FallbackTranslator` circuit breaker)**: при таймауте, ошибке `5xx` (`30 с`), исчерпании квоты `HTTP 429` (`60 с`) или ошибке авторизации `401/403` (`300 с`) проблемный провайдер уходит во временный карантин (`TRANSLATOR_COOLDOWN`), чтобы последующие запросы в Inline и Secretary Mode мгновенно шли в живой резервный API за `0 мс`, а после окончания карантина основной API автоматически возвращался в строй.
- **Мульти-ключевые цепочки `TRANSLATOR_CHAIN` и пресет `mistral`**: поддержка произвольных цепочек провайдеров со своими ключами, URL и моделями (`GROQ_API_KEY`, `GEMINI_API_KEY`, `MISTRAL_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `DEEPL_API_KEY`) с автоматической очисткой всех ключей в логах.
- **Бесключевой провайдер `mymemory` и резерв «из коробки»**: добавлен `MyMemoryTranslator` (`api.mymemory.translated.net`, до 50 000 симв./сут бесплатно с `MYMEMORY_EMAIL`); при стандартном `TRANSLATOR_PROVIDER=google` автоматическая страховка `google -> mymemory` включена по умолчанию без ключей.

## [0.3.0] — 2026-11-10

### Добавлено
- **Авто-локализация интерфейса бота (EN / RU)**: автоматический выбор языка всех меню, карточек Inline Mode, уведомлений Secretary Mode и списка команд Telegram по `from_user.language_code` (`ru`/`be`/`kk` → русский, остальные локали → английский) + ручное переключение в `/settings` и командой `/ui <en|ru|auto>`.
- **Коалесинг нажатий и отмена промежуточных запросов в Inline Mode (`INLINE_DEBOUNCE_MS`)**: короткое окно объединения нажатий (`180 мс` на промахе кэша) и мгновенная отмена незавершённого запроса пользователя при приходе более свежей строки — кратно экономит квоту LLM/DeepL и не сжигает rate-limit при быстрой печати.
- **Двусторонний авто-разворот языковой пары (`⇄`, `/swap`, `DEFAULT_SWAP_LANG`)**: если задан парный язык (например, `en ⇄ ru` или `en ⇄ pl`) и входной текст уже написан на целевом языке, бот автоматически переводит его в обратную сторону и в Inline Mode, и в Secretary Mode (`> текст`) без ручного `>lang` (мгновенно для разных алфавитов и за один вызов для LLM).
- **Публичная безопасность, `/privacy` и `/reset`**:
  - защита от закрытия тега в LLM через случайный одноразовый разделитель `<source_text_<nonce>>`, потолок ответа апстрима `1 MiB`, проверка HTTPS для ключей API и фильтр редактирования секретов в логах (`SecretRedactingFilter`);
  - разделение прав в `install.sh` (`root:root` `0755` на код/`.venv`/`install.sh`, `root:mivta` `0640` на `.env`, `mivta:mivta` `0700` + `UMask=0077` на `data/`);
  - команды `/privacy` (прозрачная политика хранения данных) и `/reset` (мгновенное удаление своих настроек из SQLite), а также флаги `python -m mivta --version` / `--check` и `Dockerfile HEALTHCHECK`.
- **Опциональный режим Webhook (`WEBHOOK_URL` + `WEBHOOK_SECRET_TOKEN`)**: встроенный HTTP-сервер на `aiohttp` с обязательной проверкой заголовка `X-Telegram-Bot-Api-Secret-Token` (автогенерация криптографического токена, если не задан вручную) и health-пробой `GET /healthz`.
