# Конфигурация (`.env`)

`mivta` читает настройки из переменных окружения и файла `.env` в рабочей директории (переменные окружения процесса имеют приоритет над `.env`). Проверить корректность конфигурации без запуска бота:

```bash
python -m mivta --check
```

---

## Полная таблица параметров

### Обязательные и провайдер перевода

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `BOT_TOKEN` | *(обязательна)* | Токен бота от `@BotFather` (формат `123456:ABC...`). |
| `TRANSLATOR_PROVIDER` | `google` | Основной провайдер: `google`, `mymemory`, `groq`, `gemini`, `mistral`, `openrouter`, `openai`, `deepl`, `libretranslate`. |
| `TRANSLATOR_CHAIN` | `""` | Полная цепочка приоритетов через запятую (например, `groq,gemini,google,mymemory`); заменяет пару `TRANSLATOR_PROVIDER` + `TRANSLATOR_FALLBACK_PROVIDER`. |
| `TRANSLATOR_API_KEY` | `""` | Ключ основного провайдера (либо используйте именные переменные `GROQ_API_KEY`, `GEMINI_API_KEY`, `MISTRAL_API_KEY`, `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `DEEPL_API_KEY`). |
| `TRANSLATOR_API_URL` | *(по пресету)* | Переопределение базового URL API (либо `<PROVIDER>_API_URL`). При передаче `API_KEY` на не-loopback хост требуется `https://`. |
| `TRANSLATOR_MODEL` | *(по пресету)* | Переопределение модели LLM (либо `<PROVIDER>_MODEL`). |
| `TRANSLATOR_TIMEOUT` | `5.0` | Таймаут HTTP-запроса к провайдеру в секундах (`> 0`). |
| `TRANSLATOR_COOLDOWN` | `30.0` | Базовое время карантина упавшего API в секундах (`30s` на таймаут/`5xx`, `2×` на `429`, `10×` на `401/403`; `0` отключает карантин). |
| `MYMEMORY_EMAIL` | `""` | Контактный email для `mymemory` (бесплатно увеличивает дневной лимит с 5 000 до 50 000 символов). |
| `ALLOW_INSECURE_HTTP_API` | `false` | Разрешить `http://` с `API_KEY` для не-локальных адресов (например, Ollama в закрытой домашней/VPC сети). |

### Резервирование и глоссарий

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `TRANSLATOR_FALLBACK_PROVIDER` | `mymemory` *(для `google`)* | Резервный провайдер или список через запятую (`none` — отключить резерв). |
| `TRANSLATOR_FALLBACK_API_KEY` | `""` | Общий ключ API для резервного провайдера (если не задан именной `<PROVIDER>_API_KEY`). |
| `TRANSLATOR_FALLBACK_API_URL` | `""` | Кастомный URL для одиночного резервного провайдера (либо `<PROVIDER>_API_URL`). |
| `TRANSLATOR_FALLBACK_MODEL` | `""` | Модель для резервного LLM-провайдера (либо `<PROVIDER>_MODEL`). |
| `TRANSLATOR_GLOSSARY` | `""` | Слова и названия через запятую, которые не должны переводиться. |

### Настройки перевода и интерфейса по умолчанию

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `DEFAULT_SOURCE_LANG` | `auto` | Исходный язык для новых пользователей (`auto` или ISO-код). |
| `DEFAULT_TARGET_LANG` | `en` | Целевой язык по умолчанию для новых пользователей. |
| `DEFAULT_SWAP_LANG` | `""` | Парный язык двустороннего авто-разворота `⇄` по умолчанию (например, `ru` или `pl`). |
| `DEFAULT_STYLE` | `neutral` | Стиль по умолчанию: `neutral`, `casual`, `formal`. |
| `DEFAULT_UI_LANG` | `ru` | Язык интерфейса бота (`ru` или `en`), если Telegram не передал `language_code` пользователя. |
| `INLINE_EXTRA_LANGS` | `""` | До 3 доп. языков карточек в Inline Mode по умолчанию (например, `pl,de`). |
| `INLINE_STYLE_VARIANTS` | `true` | Показывать карточки сразу всех 3 стилей в Inline Mode (для провайдеров со стилями). |
| `INLINE_DEBOUNCE_MS` | `180` | Окно коалесинга быстрых нажатий в Inline Mode на холодном кэше (`0..2000` мс; `0` — без ожидания). |

### Режим Webhook (опционально)

Если `WEBHOOK_URL` пуст, бот работает через **Long Polling** и не открывает входящих портов.

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `WEBHOOK_URL` | `""` | Публичный `https://` адрес (например, `https://bot.example.com/webhook`). Включает режим Webhook. |
| `WEBHOOK_SECRET_TOKEN` | *(авто)* | Секрет заголовка `X-Telegram-Bot-Api-Secret-Token` (`[A-Za-z0-9_-]{1,256}`). Если пуст — генерируется криптографически при каждом запуске. |
| `WEBHOOK_HOST` | `127.0.0.1` | Локальный адрес прослушивания `aiohttp` (рекомендуется `127.0.0.1` за Nginx/Caddy). |
| `WEBHOOK_PORT` | `8080` | Локальный порт (`1..65535`). На том же порту отвечает `GET /healthz`. |
| `WEBHOOK_PATH` | `/webhook` | HTTP-путь приёма апдейтов (не может быть `/healthz`). |

### Администрирование и карточка бота

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `OWNER_ID` | `""` | Числовой Telegram ID владельца бота (или несколько через запятую), которому доступны команды `/status`, `/update` и `/restart` в личном чате (активный провайдер цепочки, `cooldown`, аптайм, заполненность RAM-кэша, число пользователей/групп, проверка и установка обновлений, перезапуск сервиса). |
| `SYNC_BOT_PROFILE` | `true` | Автоматически выставлять при запуске локализованные RU/EN описания бота (`setMyDescription` и `setMyShortDescription`) с подстановкой `@username`. |
| `SELF_UPDATE` | `true` | Разрешить владельцу обновлять бота командой `/update` из Telegram (`false` — только вручную на сервере). |
| `SELF_RESTART` | `true` | Разрешить владельцу перезапускать бота командой `/restart` из Telegram. |
| `MIVTA_UPDATE_CMD` | `""` | Одна команда с аргументами для обновления в Docker/других схемах (например `/usr/local/bin/mivta-update`). Выполняется без shell: операторы `&&`, `\|`, `;` отклоняются. |
| `MIVTA_RESTART_CMD` | `""` | Одна команда перезапуска для Docker/других схем (например `docker restart mivta`). Если пуста — процесс подменяет сам себя, сохраняя PID. |
| `MIVTA_UPDATE_REPO` | `RUdolf1517/mivta` | Репозиторий `owner/repo`, релизы которого проверяются командой `/update`, когда локальный `git` недоступен. |
| `MIVTA_BRANCH` | `main` | Ветка, которую проверяет `/update` и которую тянет `install.sh`. |
| `MIVTA_UPDATE_TRIGGER` | *(авто)* | `1` / `0` — включить или выключить запрос обновления через маркер в `data/` (по умолчанию включается, если установлен юнит `mivta-update.path`). |
| `MIVTA_INSTALL_DIR` | *(авто)* | Каталог установки (`/opt/mivta`); задаётся автоматически systemd-юнитом, вручную нужен только для нестандартных схем. |

### Хранилище и эксплуатационные лимиты

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `DATABASE_PATH` | `data/mivta.db` | Путь к SQLite-базе настроек пользователей (`:memory:` для тестов). |
| `MAX_TEXT_LENGTH` | `500` | Максимальная длина переводимого сообщения (`1..4096`). |
| `CACHE_TTL` | `300` | Время жизни записей RAM-кэша в секундах (`0` отключает кэш). |
| `CACHE_MAX_SIZE` | `512` | Максимум записей в LRU-кэше (`0` отключает кэш). |
| `RATE_LIMIT_PER_MINUTE` | `30` | Скорость пополнения лимита запросов на одного `user_id` в минуту. |
| `RATE_LIMIT_BURST` | `15` | Максимальный разовый всплеск запросов на одного `user_id`. |
| `MAX_CONCURRENT_TRANSLATIONS` | `20` | Общий семафор одновременных запросов к внешнему API переводчика. |
| `LOG_LEVEL` | `INFO` | Уровень логов: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`. |
