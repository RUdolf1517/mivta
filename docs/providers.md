# Провайдеры перевода, автозамена API и глоссарий

Пакет `mivta.translator` изолирован от `aiogram`, SQLite и конфигурации приложения: все провайдеры работают поверх общего пула соединений `httpx.AsyncClient` с жёстким таймаутом и потолком тела ответа `1 MiB`.

---

## Поддерживаемые провайдеры

| Провайдер | Ключ API | Стили (`neutral` / `casual` / `formal`) | Модель / Узел по умолчанию | Особенности |
| :--- | :---: | :---: | :--- | :--- |
| `groq` | Да | 1 батч-вызов на 3 стиля | `llama-3.3-70b-versatile` (`api.groq.com/openai/v1`) | Минимальная задержка среди LLM (~150–250 мс), бесплатный тариф без карты. |
| `gemini` | Да | 1 батч-вызов на 3 стиля | `gemini-2.5-flash` (`generativelanguage.googleapis.com`) | OpenAI-совместимый эндпоинт Google AI Studio, бесплатный Free Tier. |
| `mistral` | Да | 1 батч-вызов на 3 стиля | `mistral-small-latest` (`api.mistral.ai/v1`) | Быстрый европейский LLM с бесплатным планом Experiment. |
| `openrouter` | Да | 1 батч-вызов на 3 стиля | `openai/gpt-4o-mini` (`openrouter.ai/api/v1`) | Доступ к любым платным и `:free` моделям через `OPENROUTER_MODEL`. |
| `openai` | Да | 1 батч-вызов на 3 стиля | `gpt-4o-mini` (`api.openai.com/v1`) | Официальный API OpenAI или любой совместимый сервер (Ollama, vLLM, LiteLLM). |
| `deepl` | Да | Нативный `formality` | `api-free.deepl.com` (`:fx`) или `api.deepl.com` | Автовыбор Free/Pro эндпоинта по суффиксу `:fx` ключа, сохранение разметки через XML-теги `<sN>`. |
| `libretranslate` | Опционально | Нет | `localhost:5000` или свой URL | Удобен для полностью автономного self-hosted контура. |
| `google` | Не нужен | Нет | `translate.googleapis.com` → `clients5.google.com` → `translate.google.com` | Работает «из коробки» только с `BOT_TOKEN`; автоматически обходит `429` между узлами Google и страхуется провайдером `mymemory`. |
| `mymemory` | Не нужен | Нет | `api.mymemory.translated.net/get` | Независимый бесплатный REST API без регистрации (5 000 симв./сут анонимно или 50 000 симв./сут при указании `MYMEMORY_EMAIL`). |

## Автоматическая замена недоступных API и карантин (`FallbackTranslator`)

По умолчанию при `TRANSLATOR_PROVIDER=google` уже включена автоматическая связка **`google → mymemory`** без единого ключа (отключить резерв полностью можно через `TRANSLATOR_FALLBACK_PROVIDER=none`).

Для объединения нескольких бесплатных или платных API в единую цепочку задайте **`TRANSLATOR_CHAIN`** и индивидуальные переменные `<ПРОВАЙДЕР>_API_KEY`:

```dotenv
TRANSLATOR_CHAIN=groq,gemini,mistral,google,mymemory
GROQ_API_KEY=gsk_...
GEMINI_API_KEY=AIza...
MISTRAL_API_KEY=...
MYMEMORY_EMAIL=you@example.com
```

Как работает умное переключение (circuit breaker):
- При сбое провайдера запрос мгновенно уходит в следующий здоровый API цепочки.
- Упавший провайдер ставится на временный **карантин** (`TRANSLATOR_COOLDOWN=30` сек для таймаутов и `5xx`, `60` сек при исчерпании лимита `429`, `300` сек при ошибке ключа `401/403`). Пока длится карантин, новые сообщения в Inline и Secretary Mode идут **сразу в рабочий резерв за `0 мс`**, не ожидая повторного таймаута.
- По истечении карантина основной провайдер автоматически проверяется и при успешном ответе возвращается на первое место.
- Локальные ошибки ввода (пустая строка, превышение `MAX_TEXT_LENGTH`) отклоняются сразу и не запускают перебор цепочки.

## Глоссарий непереводимых терминов

Переменная `TRANSLATOR_GLOSSARY` принимает список имён собственных, брендов и терминов через запятую:

```dotenv
TRANSLATOR_GLOSSARY=mivta, Kubernetes, Play2Go, PostgreSQL
```

- Для **LLM-провайдеров** (`groq`, `gemini`, `mistral`, `openrouter`, `openai`) термины передаются в системной инструкции модели, чтобы модель корректно склоняла окружающий текст, оставляя сами слова без перевода.
- Для **классических провайдеров** (`google`, `mymemory`, `deepl`, `libretranslate`) и смешанных цепочек резерва `mivta` маскирует совпадения по границам слов токенами-плейсхолдерами до отправки и восстанавливает их после перевода.

## Двусторонний авто-разворот (`⇄`)

Когда у пользователя задан парный язык (`/swap ru` или `DEFAULT_SWAP_LANG=ru` при целевом `en`) и исходный язык стоит в `auto`:

1. **Разные письменности (`en ⇄ ru`, `en ⇄ uk`, `en ⇄ he`, `en ⇄ zh` и др.)**: направление определяется локально по Unicode-скрипту текста за `0` дополнительных сетевых вызовов.
2. **Один алфавит (`en ⇄ pl`, `en ⇄ de`)**:
   - LLM-провайдеры определяют язык и переводят в нужную сторону за **1 вызов**;
   - детекторные провайдеры (`google`, `mymemory`, `deepl`) разворачивают направление автоматически, если определённый исходный язык совпал с целевым.
